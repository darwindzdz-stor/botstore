# Bot Store Hardening Pass

هذه التعديلات جزء من نفس المشروع وليست نسخة مستقلة.

## تم إصلاحه
- مصادقة Telegram أصبحت مطلوبة فعليًا عند إصدار session جديدة؛ لا يمكن استخدام session قديمة بدل `initData`.
- sessions تستخدم SHA-256 لتخزين token hashes، مع TTL وحد أقصى للجلسات وتحديث `last_used_at`.
- قبول Origin أصبح متوافقًا مع Telegram Web وsame-origin مع إمكانية إضافة `ALLOWED_ORIGINS`.
- API يرفض طلبات الكتابة التي لا تستخدم JSON.
- ترتيب routers يضمن وصول `/api/admin/*` إلى لوحة الإدارة قبل 404 الخاص بالـ API العام.
- روابط البوتات يجب أن تطابق username، وتُرفض fragments والمسارات الإضافية.
- الإحصائيات الخاصة بالمشاهدات/الفتحات لا تُحتسب للزائر المجهول.
- تقليل ضجيج search events وعدم تسجيل الاستعلامات القصيرة جدًا.
- تنظيف sessions/events/audit دوريًا مع الاحتفاظ بنسخ احتياطية محدودة.
- قاعدة البيانات ونسخها الاحتياطية تُنشأ بصلاحيات ملفات ومجلدات مقيدة.
- السيرفر يستمع على `127.0.0.1` افتراضيًا بدل تعريض Termux للشبكة المحلية، ويمكن تغييره صراحةً عبر `HOST`.
- الواجهة تستخدم مهلة طلب 15 ثانية ومنع race conditions بين عمليات البحث المتتالية وdebounce للبحث.
- HTML يصبح `no-cache` والأصول قصيرة التخزين لتجنب بقاء JS قديم بعد النشر.
- لا توجد دوال تنفيذ كود مثل `eval` أو `new Function` في الواجهة.

## التحقق
- تم تشغيل `node --check` على ملفات JavaScript الرئيسية ونجحت.
- محاولة `npm install` في بيئة البناء انتهت بمهلة ولم تنتج `node_modules` أو `package-lock.json`؛ لذلك لم يتم الادعاء بأن `npm test` أو `npm audit` تم تشغيلهما.
